# Como contribuir

Agradecemos contribuições de design, acessibilidade, QA, conteúdo, comunicação, documentação e desenvolvimento.

## Antes de começar

1. Consulte o `README.md`, `GOVERNANCE.md` e `ACCESSIBILITY.md`.
2. Procure uma Issue existente antes de criar outra.
3. Para mudanças estruturais, abra uma RFC antes da implementação.
4. Nunca inclua dados pessoais, credenciais ou materiais sem autorização.

## Fluxo recomendado

1. Crie ou escolha uma Issue.
2. Use uma branch com nome descritivo, como `artefato/banner-github` ou `docs/spec-0004`.
3. Faça mudanças pequenas e relacionadas.
4. Atualize documentação, catálogo e changelog quando aplicável.
5. Abra um Pull Request descrevendo finalidade, impacto e testes.
6. Responda às revisões e preserve o histórico das decisões.

## Commits

Prefira mensagens objetivas no formato:

```text
categoria: descrição breve
```

Categorias comuns:

- `docs`
- `feat`
- `fix`
- `assets`
- `a11y`
- `refactor`
- `chore`

Exemplo:

```text
a11y: documenta alternativa textual do banner institucional
```

## Pull Requests

O Pull Request deve informar:

- problema ou necessidade;
- solução proposta;
- arquivos afetados;
- impactos de acessibilidade;
- validações realizadas;
- artefatos substituídos ou relacionados;
- Issue correspondente.

## Critérios mínimos

A contribuição deve:

- seguir a nomenclatura oficial;
- preservar compatibilidade e rastreabilidade;
- não depender apenas de informação visual;
- incluir documentação suficiente para reutilização;
- evitar duplicação de ativos;
- respeitar licenças e direitos autorais.

## Revisão acessível

Comentários devem apontar o arquivo, o problema, o impacto e uma sugestão concreta. Evite instruções baseadas apenas em posição visual, como “arrume o item vermelho à direita”.
