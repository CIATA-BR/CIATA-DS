# Revised Section 508

A Revised Section 508 estabelece requisitos de acessibilidade para tecnologia da informação e comunicação coberta pela legislação federal dos Estados Unidos.

## Base normativa

A Revised 508 Standards incorpora por referência os critérios de sucesso e requisitos de conformidade da **WCAG 2.0 nos níveis A e AA** para conteúdo Web e, com adaptações e exceções específicas, também para conteúdo e software não Web.

A Section 508 não deve ser tratada como sinônimo de WCAG. Além da incorporação de WCAG 2.0, existem requisitos próprios de escopo, software, hardware, documentação e suporte.

## Regra CIATA

O alvo interno da CIATA permanece **WCAG 2.2 A e AA**.

Quando Section 508 for aplicável, a avaliação deve manter duas leituras simultâneas:

1. verificar o atendimento da base interna WCAG 2.2;
2. verificar separadamente a conformidade com os requisitos formais da Revised Section 508.

Atender WCAG 2.2 normalmente cobre e excede diversos requisitos WCAG incorporados pela Section 508, mas não autoriza uma declaração automática de conformidade com Section 508.

## Conteúdo e software não Web

Ao aplicar os critérios WCAG 2.0 incorporados a documentos e software não Web, devem ser observadas as adaptações e exceções previstas pela Revised 508 Standards.

Entre as exceções indicadas pelo U.S. Access Board para conteúdo e software não Web estão os critérios WCAG 2.0:

- 2.4.1 Bypass Blocks;
- 2.4.5 Multiple Ways;
- 3.2.3 Consistent Navigation;
- 3.2.4 Consistent Identification.

A aplicabilidade não deve ser inferida apenas a partir do número do critério; deve ser confirmada no requisito formal correspondente.

## ICT Testing Baseline

Para Web, o U.S. Access Board mantém o **ICT Testing Baseline for Web**, que descreve testes mínimos e orientações para determinar conformidade com os requisitos Web da Revised Section 508.

A baseline deve ser tratada como referência de consistência de teste, não como substituta de um processo completo de avaliação.

## Escopo da avaliação

Registrar antes do teste:

- produto e versão;
- entidade ou contrato que exige Section 508;
- superfícies Web, software, documentos, hardware e suporte incluídos;
- requisitos aplicáveis;
- exceções e não aplicabilidades justificadas;
- ambientes de teste;
- tecnologias assistivas utilizadas.

## Evidência

Para cada requisito aplicável, registrar:

- referência normativa;
- relação com WCAG, quando houver;
- método de teste;
- ambiente;
- resultado observável;
- defeitos ou limitações;
- justificativa para não aplicabilidade ou exceção.

## ACR / VPAT

Quando a avaliação resultar em um ACR:

- usar a **VPAT® 508 Edition** quando o relatório for específico para Revised Section 508;
- usar a **VPAT® INT Edition** quando o mesmo relatório também cobrir EN 301 549 e/ou WCAG;
- seguir o [guia interno de preenchimento](../vpat/guia-de-preenchimento.md);
- não elevar o nível declarado apenas porque o produto atende a uma versão mais recente da WCAG internamente.
