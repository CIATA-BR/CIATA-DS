# Checklist de entrada do acervo do Nexo

Use este checklist antes de aprovar um novo asset do Nexo para o repositório.

## Identidade visual

- [ ] usa a referência canônica vigente do Nexo;
- [ ] preserva visor escuro, olhos verdes, cabelo amarelo e corpo branco/prata com azul e amarelo;
- [ ] preserva proporções, linguagem 3D/cartoon e formas arredondadas;
- [ ] não introduz acessório permanente ou mudança estrutural sem versionamento de identidade;
- [ ] gesto, expressão e estado são coerentes com a finalidade declarada.

## Acessibilidade

- [ ] o asset está classificado como decorativo, informativo, funcional ou complexo;
- [ ] possui descrição curta de catálogo;
- [ ] possui descrição longa quando a imagem for complexa;
- [ ] não usa cor, gesto, expressão ou símbolo como única fonte de informação funcional essencial;
- [ ] não contém texto rasterizado essencial quando a informação puder ser texto real;
- [ ] quando decorativo, pode ser ignorado por tecnologias assistivas na implementação;
- [ ] quando animado, possui alternativa estática ou de movimento reduzido quando necessária.

## Qualidade técnica

- [ ] o nome do arquivo segue a convenção vigente;
- [ ] formato, dimensões e proporção são adequados ao uso;
- [ ] transparência foi preservada quando necessária;
- [ ] não existem artefatos visuais relevantes, cortes ou deformações;
- [ ] o asset continua reconhecível em tamanho reduzido;
- [ ] o arquivo não é duplicata exata de outro asset;
- [ ] similaridades visuais relevantes foram revisadas conforme a política de duplicidade.

## Governança

- [ ] há entrada no catálogo mestre;
- [ ] os campos obrigatórios de metadados estão preenchidos;
- [ ] a origem do asset está registrada;
- [ ] a referência canônica usada está identificada;
- [ ] o status inicial foi definido;
- [ ] a aprovação humana foi registrada antes de marcar como `aprovado` ou `canonico`.

## Antes do merge

- [ ] o PR altera apenas o necessário;
- [ ] novos caminhos ou nomes não quebram referências existentes;
- [ ] o README ou índices foram atualizados quando necessário;
- [ ] nenhuma imagem redundante foi adicionada por engano;
- [ ] a descrição do PR informa finalidade, contexto e impacto do novo asset.
